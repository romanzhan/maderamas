# 0002. Собственный слой перевода вместо WPML / Polylang

**Дата:** 2026-07-29
**Статус:** принято

## Контекст

Сайт запускается на испанском, нужен английский, в перспективе португальский и русский.
Бесплатного способа перевести товары WooCommerce фактически нет: Polylang в бесплатной
версии не переводит товары, TranslatePress free ограничен одним дополнительным языком,
WPML и Polylang Pro стоят порядка $99 в год. Заказчик от подписок уходит осознанно.

Каталог небольшой — значит собственный слой окупается.

## Решение

Модуль `wp-content/mu-plugins/maderamas-i18n/`.

**Модель данных: один пост на все языки, переводы в `post_meta`.**

Ключевая причина — склад. WPML и Polylang дублируют пост на каждый язык. Для товара
WooCommerce это означает, что цена и остаток существуют в нескольких экземплярах
и их надо синхронизировать. Рассинхрон склада между языками — типовая и дорогая
ошибка мультиязычных магазинов. При хранении переводов в мета-полях товар остаётся
один: одна цена, один остаток, одна карточка в админке.

Состав слоя:

1. Определение языка по префиксу URL (`es` — без префикса, остальные — `/en/…`).
2. Фильтр `locale` переключает локаль WordPress. Это бесплатно переводит **все строки
   ядра и WooCommerce** — корзину, чекаут, письма, кнопки — штатными `.mo`-файлами.
   Руками остаётся перевести только контент.
3. Подмена контента фильтрами `the_title`, `the_content`, `get_the_excerpt`, `the_post`
   с фолбэком на испанский.
4. Термины и ярлыки атрибутов Woo — через term meta и `woocommerce_attribute_label`.
5. Метабокс с вкладками по языкам в админке товара и страницы.
6. Язык заказа пишется в `_maderamas_order_lang`; письма формируются на языке заказа,
   а не на языке администратора.
7. `posts_search` дополнительно ищет по мета-полям перевода.
8. `hreflang` и языковые версии в sitemap.

## Осознанные ограничения

- Сторонние плагины, читающие заголовки напрямую из БД, переводов не увидят.
- Экспорт товаров и WooCommerce REST API отдают язык по умолчанию.
- Слаги в первой версии одинаковы для всех языков, различается только префикс.
  Переводимые слаги заметно усложняют rewrite-логику ради небольшого выигрыша в SEO.
- Это наш код, и поддерживать его нам. Если каталог вырастет в разы, покупка WPML
  может оказаться дешевле поддержки — решение стоит пересмотреть.
