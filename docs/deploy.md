# Деплой

> **Статус:** хостинг ещё не выбран. Workflow `.github/workflows/deploy.yml` написан,
> но выключен — он запускается только если в настройках репозитория задана
> переменная `DEPLOY_ENABLED=true`. Пока её нет, деплой не срабатывает.

## Главное правило

Данные движутся строго в одну сторону по каждому типу:

```
КОД      локалка → git → прод      (тема и mu-plugins)
КОНТЕНТ  прод → локалка            (база данных и uploads)
```

Деплой **никогда** не трогает базу данных, `wp-content/uploads`, ядро WordPress
и сторонние плагины. Поэтому затереть каталог заказчика деплоем физически невозможно.

## Что происходит при push в `main`

1. CI прогоняет линтеры.
2. `npm ci && npm run build` — собираются ассеты темы.
3. `rsync` по SSH копирует на прод только:
   - `wp-content/themes/maderamas/` (вместе со свежесобранным `build/`)
   - `wp-content/mu-plugins/`

## Что нужно настроить перед первым деплоем

В GitHub: Settings → Secrets and variables → Actions.

**Секреты:**

| Имя | Что это |
| --- | --- |
| `DEPLOY_SSH_KEY` | Приватный SSH-ключ для доступа на прод (отдельный ключ только для деплоя) |
| `DEPLOY_HOST` | Хост сервера |
| `DEPLOY_USER` | Пользователь SSH |
| `DEPLOY_PATH` | Абсолютный путь до `wp-content` на проде |

**Переменные:**

| Имя | Значение |
| --- | --- |
| `DEPLOY_ENABLED` | `true`, чтобы включить деплой |
| `DEPLOY_PORT` | Порт SSH, если не 22 |

## Ключи Mercado Pago

Плагин Mercado Pago хранит ключи в настройках WordPress, то есть в базе данных.
База не версионируется и не деплоится, поэтому ключи в git не попадают в принципе.

На каждой среде ключи вводятся в админке отдельно: на локалке — sandbox, на проде —
боевые. Боевые ключи не должны существовать нигде, кроме прода: ни в дампах базы,
которые снимают на локалку, ни в скриншотах, ни в переписке.

## Как снять контент с прода на локалку

```bash
# на проде
wp db export dump.sql
tar czf uploads.tar.gz wp-content/uploads

# локально, после копирования файлов
npm run wp -- db import dump.sql
npm run wp -- search-replace 'https://maderamas.com.ar' 'http://localhost:8888'
```

`search-replace` обязателен — без него ссылки и картинки будут вести на прод.

## Перед первым боевым деплоем

1. Сделать полный бэкап прода (файлы + база).
2. Прогнать деплой на staging или на копии сайта.
3. Проверить, что после деплоя открывается главная, карточка товара и чекаут.
