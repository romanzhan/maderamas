# 016 — Корзина/чекаут: формы

**Статус:** готово, 2026-08-18.

## Особенность этой задачи

Поля `woocommerce/checkout` (адрес, email, способ доставки/оплаты)
рендерятся **на клиенте** — в отданном сервером HTML их физически нет
(React/Interactivity API, как и мини-корзина/сортировка из задач
011/014, только тут ещё и сами поля, не только кнопки). `curl` этого
не увидит в принципе — не браузер и не JS-движок.

Вместо догадок «на глаз» — классы взяты из **собственного собранного
CSS WooCommerce**
(`wp-content/plugins/woocommerce/assets/client/blocks/checkout.css` в
контейнере wp-env): это тоже структурная проверка (файл, не браузер),
но по факту наличия класса в реальном коде плагина, а не по памяти
или предположению. Так нашлись: `.wc-block-components-text-input`
(+`__wrapper`), `.wc-block-components-select-input`,
`.wc-block-components-radio-control__input`,
`.wc-block-components-checkbox__input`, `.wc-block-components-button`.

## Что сделано

- Текстовые поля/select — визуальный язык `.field`/`.select` (рамка/
  радиус/фон на токенах), фокус — `box-shadow: var(--wp--preset--shadow--focus)`
  (тот же токен, что и в `.field`/`.select`/`.variations select` из
  задач 010/015 — везде одно кольцо фокуса).
- Радио/чекбоксы (способ доставки, «сохранить данные» и т.п.) —
  `accent-color: var(--wp--preset--color--primary)`. Это современный,
  не самодельный способ перекрасить нативный контрол (широко
  поддерживается браузерами, не требует кастомной пересборки
  чекбокса/радио через `<span>`+CSS-трюки).
- Кнопки (`Finalizar compra`, `Aplicar cupón` и т.п.) — визуальный
  язык `.btn-primary`, `focus-visible` — тот же outline-токен, что
  везде на сайте.
- `@tailwindcss/forms` тут прямо не участвует (strategy:"class", Woo
  сама не проставляет `form-input`/`form-select` на свои React-поля) —
  это ожидаемо, не пробел, обсуждали при выборе strategy в задаче 010.

## Проверено (без браузера)

- `npm run build`/`lint:css` — чисто.
- Классы подтверждены наличием в `checkout.css` самого плагина WooCommerce
  (см. выше) — структурная проверка вместо угадывания.
- `curl` с сохранённой сессией (товар добавлен через
  `?wc-ajax=add_to_cart`, иначе `/checkout/` редиректит на пустую
  корзину) — `/cart/` и `/checkout/` дают 200.
- Новые классы (`wc-block-components-text-input`,
  `wc-block-components-button`) подтверждены в собранном
  `build/style-index.css`; `--wp--preset--shadow--focus` подтверждена
  как реальная CSS-переменная в отданном HTML.
- `debug.log` — без новых ошибок.
- **Не проверено визуально** — поля рендерятся в браузере, самопроверка
  этой конкретной задачи структурно неполна по объективной причине
  (нет данных до JS-рендера), заказчику стоит explicitly глянуть именно
  `/checkout/` при личной проверке.
