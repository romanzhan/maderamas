# 002 — Сбор и парсинг данных о товарах

**Статус:** в работе, запущено 2026-08-18. Готово: Tiendanube. В процессе:
Mercado Libre, Word-документ + Drive.

## Промежуточные находки (Tiendanube, готово)

Полный обход `maderamas.com.ar/productos/` — 8 товаров, совпадает с
ожиданием. Данные — `scratchpad/product-data/tiendanube.md` (вне git).

⚠️ **Важно для модели атрибутов, требует решения пользователя:**
на Tiendanube **нет отдельного атрибута «порода дерева»** — материал
везде указан одинаково: «MDF 18 mm». Значения вроде «Roble Americano»,
«Nogal», «Blanco», «Crudo» на деле — это **цвет/отделка**, не порода
дерева. `docs/content-guide.md` сейчас предполагает раздельные `pa_color`
и `pa_madera` (реальные значения из старого магазина, ещё не сверены) —
это расходится с находкой. Также замечен баг на самом Tiendanube:
на странице «Silla Evolutiva Infantil (Nogal)» свотч цвета подписан
«Roble Americano» (явная нестыковка название/атрибут на боевом сайте).
Не резолвим сами — ждём подтверждения по остальным источникам и решения
пользователя, как моделировать атрибуты (один `pa_color`/`pa_acabado`
вместо пары `pa_color`+`pa_madera`?).

SKU нигде не публикуется, статус наличия явно не указан (кнопка «Agregar
al carrito» была активна везде — наличие подразумевается косвенно).

## Зачем

Заказчик отдельно подчеркнул: это самая важная и самая сложная часть
(наполнение сайта товарами) и требует серьёзной, глубокой проработки —
не поверхностного прохода по одной странице, а обхода всего ассортимента
по всем источникам, со сверкой между ними.

## Источники (см. ссылки в `CREDENTIALS.local.md`)

1. **Mercado Libre** — магазин продавца «Madera Más». Обойти **весь**
   каталог постранично/по категориям (не одну страницу «Productos
   recomendados»), собрать по каждой позиции: название, цена, старая
   цена/скидка, описание, характеристики (материал, размеры, вес/нагрузка,
   возраст), все фото, отзывы/рейтинг если есть.
2. **Tiendanube** (`maderamas.com.ar` — боевой магазин). Обойти весь
   каталог, собрать по каждому из 8 товаров: название, цена, полное
   описание, все фото, атрибуты (`pa_color`, `pa_madera` и т.д.).
3. **Word-документ «ассортимент»** (Google Docs, заказчица). Разобрать
   по позициям: там уже видно название/цену/материал/размеры/возраст/
   нагрузку/фото — но нужен полный проход по всем страницам документа,
   не только первый экран.
4. **Google Drive, папка «Фотосессия»**. Составить опись: что лежит в
   каждой из 7 подпапок (файлы, разрешение, к какому товару/отделке
   относится), чтобы потом сопоставить с финальным ассортиментом.

## Формат результата

Структурированные данные (markdown-таблицы или JSON — на усмотрение
исполнителя, лишь бы легко сверялось) **вне git** — в scratchpad или
рабочей директории, не в репозитории (сырые данные заказчика в git не
идут, см. `CLAUDE.md`). По каждой позиции — сведение из всех источников
в одну карточку с пометкой, откуда что взято, и явным флагом на
расхождениях (цена/название/материал не совпадают между источниками).

## Дальше

Расхождения — не додумывать, выносить пользователю на решение. После
сведения — обновить `docs/content-guide.md` (сейчас там заглушки для
атрибутов `pa_color`/`pa_madera`) и переходить к наполнению WooCommerce
(задача 008).
