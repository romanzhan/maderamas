# 003 — Главная: шапка + промо-полоса + hero с каруселью

**Статус:** готово (первая версия), 2026-08-18. Визуально в браузере не
смотрели (ревью-политика — см. `CONTEXT.md`), но задеплоено на staging
и проверено, что страница реально открывается без фатальных ошибок.

## Что сделано

- `parts/header.html` — промо-полоса (bg `promo-electric`, бейдж «ENVÍO
  GRATIS» жёлтым, пилл «6 cuotas sin interés», скрыт на очень узких
  экранах) + основная шапка (вордмарк `madera`+`más` двухцветный,
  `core/navigation` с автоматическим переключением в бургер-меню на
  мобильном — `overlayMenu:"mobile"`, скрыт на `<lg`, поиск скрыт на
  `<md`, `woocommerce/mini-cart` всегда виден).
- `patterns/hero.php` — 2 колонки на `md+` (`grid md:grid-cols-2`),
  на мобильном текст сверху/картинка снизу через `order-*`. Левая
  колонка — обычные WP-блоки (Heading/Paragraph/Buttons), редактируемые
  из админки. Правая — карусель на **Swiper** (`core/html`, т.к. блокам
  такое не сделать), 3 слайда-заглушки, точки пагинации + стрелки,
  автоплей 6с (отключается при `prefers-reduced-motion`).
- `templates/front-page.html` — новый файл, специально для главной
  (раньше не было, WP использовал бы `index.html`).
- `src/carousels.js` — общий инициализатор Swiper по `.js-swiper`,
  настройки через `data-*` атрибуты — переиспользуется в задаче 004+
  (продуктовые слайдеры, отзывы), не переписываем заново.

## Технические грабли (на будущее)

- **`@wordpress/scripts` делит CSS на два файла**, если стили сторонней
  библиотеки импортируются из JS (`import 'swiper/css'` в
  `carousels.js`), а не из `style.css`: наш Tailwind уходит в
  `build/style-index.css`, а CSS Swiper — в отдельный `build/index.css`.
  Оба теперь подключаются в `functions.php` (`maderamas_enqueue_assets`)
  — если добавляете ещё одну JS-библиотеку со своим CSS, она попадёт
  туда же, второй раз заводить enqueue не нужно.
- **Webpack-кэш `node_modules/.cache` не инвалидируется**, когда меняются
  только PHP/HTML-файлы, которые сканирует Tailwind (webpack не знает
  про них — знает только про CSS/JS-граф зависимостей). После правки
  классов в `.html`/`.php`-шаблонах, если новые классы не появляются в
  собранном CSS — сначала `rm -rf node_modules/.cache`, потом `npm run build`.
- **`.html`-файлы в `templates/`/`parts/` не выполняют PHP** — в отличие
  от `patterns/*.php`. `esc_html__()`/`home_url()` там не сработают,
  будет буквальный текст `<?php ... ?>` на странице. В `parts/header.html`
  поэтому — литеральный испанский текст и `href="/"` вместо `home_url()`.
  Тексты страниц/товаров всё равно идут через `Maderamas_Lang`
  (`post_meta`) — это ограничение касается только статичной «обвязки»
  темы (шапка/футер/лого), не контента.
