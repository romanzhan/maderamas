# 010 — Дизайн-система: фундамент для полного визуального ревью

**Статус:** фундамент готов, 2026-08-18. Остальные подзадачи (011–017,
см. `README.md`) — по ходу.

## Зачем

Полная перестройка визуала сайта по прямому запросу заказчика: каждый
DOM-элемент должен быть проработан (стилизация + интерактивность),
никаких браузерных стилей по умолчанию, никаких самодельных SVG,
типографика меньше и мобайл-фёрст, карточки товаров плотнее (3–4 в ряд),
галерея товара — на нормальной библиотеке. Полный список требований —
в истории чата, не дублируется здесь.

Процессные ограничения на время этой фазы: работаем локально
(`localhost:8888`, wp-env/Docker), самопроверка — только структурно
(build/lint/curl/wp-cli), без браузерных скриншотов; на staging не
деплоим, пока заказчик сам не посмотрит локально и не подтвердит.

## Что сделано в этом куске (фундамент)

- **Иконки** — `lucide-static` (npm) как единственный источник SVG на
  сайте. 13 файлов скопированы в `assets/icons/` (chevron-*, search,
  shopping-cart, menu, x, plus, minus, trash-2, check, circle-user).
  Хелпер `maderamas_icon( $name, $classes, $attributes )` в
  `functions.php` инлайнит файл, снимает класс `lucide`, добавляет
  `aria-hidden="true"` по умолчанию и произвольные классы/атрибуты.
- **Формы** — `@tailwindcss/forms` подключён с `strategy: 'class'`
  (осознанно: плагин трогает только элементы с явными классами
  `form-input`/`form-select`, не все `<input>`/`<select>` сайта огулом).
- **Типографика** — `theme.json` → `settings.typography.fontSizes`
  пересчитан на меньшую, мобайл-фёрст шкалу: было `xxx-large` до
  4.25rem (68px), стало до 2.75rem (44px) на десктопе / 1.875rem (30px)
  на мобильном. Вся шкала (small…xxx-large) сдвинута вниз пропорционально.
  Заодно найден и исправлен конкретный баг — `templates/single-product.html`
  переиспользовал `xxx-large` (токен главного H1) для заголовка товара;
  теперь `xx-large`.
- **Тени/переходы** — добавлены `settings.shadow.presets[].slug: "focus"`
  (кольцо фокуса) и `settings.custom.duration` (`fast`/`base`/`slow` —
  150/220/350ms) в `theme.json`, прокинуты в Tailwind как
  `shadow-focus`/`duration-*`.
- **Компонентный CSS-слой** — `@layer components` в `src/style.css`:
  `.btn-primary`/`.btn-outline`/`.btn-ghost` (44px мин. высота — Apple
  HIG), `.icon-btn` (круглая 44×44 кнопка), `.field`/`.select`
  (на базе `@tailwindcss/forms`, с явными hover/focus/disabled/aria-invalid),
  `.select-wrapper` + `.maderamas-icon` оверлей (шеврон — из
  `maderamas_icon()`, а не фоновая картинка плагина форм — одна иконка
  на весь сайт без исключений), `.card`, `.badge`/`.badge-accent`/
  `.badge-success`.

## Важная находка: коллизия токенов spacing/radius с Tailwind

Изначальный план — прокинуть `theme.json`'s `spacingSizes` (слаги
`10`/`20`/`30`/`40`/`50`/`60`) и кастомную шкалу радиусов
(`sm`/`md`/`lg`/`xl`) в Tailwind напрямую как `spacing`/`borderRadius`.

**Это ломало уже написанные секции.** Числовые слаги `10`/`20`/`40`/`60`
и именованные `sm`/`md`/`lg`/`xl` — это одновременно и ключи стоковой
шкалы Tailwind, которая уже используется в `hero.php`, `footer.html`,
`archive-product.html` и др. (`gap-10`, `rounded-lg`, `rounded-2xl`) с
их штатным (стоковым) значением. Слияние тихо переопределило бы эти
классы новыми числами — например, `rounded-lg` стал бы вдвое крупнее.
Проверено `grep` по всей теме перед мержем — коллизия подтверждена на
9 местах. **Решение:** `spacingSizes`/`radius` из `theme.json` НЕ
мержатся в Tailwind; новые компоненты используют стоковую шкалу
Tailwind напрямую (она и так согласована сама с собой). `spacingSizes`
остаются доступны в блочном редакторе через `var(--wp--preset--spacing--*)`,
как и раньше — тут никто их не терял. Комментарий с объяснением оставлен
прямо в `tailwind.config.js`, чтобы в задачах 011+ никто не наступил
на те же грабли.

## Важная находка: Tailwind JIT «съедает» ещё не использованные компоненты

После сборки в `build/style-index.css` не оказалось `.btn-primary`,
`.icon-btn`, `.card`, `.badge-accent`/`.badge-success`, `.select-wrapper`
(при этом `.field`/`.select`/`.badge` — попали). Не баг: Tailwind v3 в
JIT-режиме генерит правило для **любого** класса — как автоматического
utility, так и вручную написанного в `@layer components` — только если
имя класса найдено текстовым поиском где-то в `content`
(`wp-content/themes/maderamas/**/*.{php,html,js}` +
`wp-content/mu-plugins/**/*.php`). Уцелевшие классы совпали случайно —
подстрока `field` нашлась в `$field` где-то в mu-plugins, `select`/`card`
— в бандле Swiper (`build/index.js`, тоже под content-глобом), `badge` —
в PHP-массиве `'badge' => ...` из `hero.php`. Это ожидаемое поведение,
не поломка: как только классы `.btn-primary`, `.card` и т.д. реально
появятся в разметке (задачи 011–017), Tailwind их сгенерит. **Важно
для следующих задач:** имена классов в PHP/HTML нужно писать
литеральной строкой, не собирать конкатенацией — динамически
собранные имена JIT не увидит и отбросит.
