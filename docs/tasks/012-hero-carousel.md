# 012 — Hero: карусель с самостоятельными слайдами

**Статус:** готово, 2026-08-18. Два раунда правок по фидбэку заказчика
после локального просмотра — детали в конце файла.

## Было

Текст (заголовок/бейдж/кнопки) — статичный слева, крутилась только
картинка справа (плейсхолдеры-шашечки). Не совпадало с референсом
(roststul.ru), где каждый слайд — цельное предложение.

## Стало

`patterns/hero.php` полностью переписан: каждый `.swiper-slide` — весь
блок целиком (свой фон-градиент на токенах, бейдж, заголовок, текст,
цена, две кнопки, фото товара), edge-to-edge (`align:"full"`).

**Данные — реальные, не плейсхолдеры.** Три уже загруженных товара
(`wc_get_product()` по ID из `bin/seed-products.php`): Silla Evolutiva
Infantil (флагман), Silla Alta de Comer Evolutiva, Set Mesa + 2 Sillas
Montessori (новая линейка). Из каждого товара берутся: настоящее фото
(`get_image_id()` + `wp_get_attachment_image_url()`), цена
(`get_price_html()` — так подхватывается «Desde …» для variable-товаров
и локальное форматирование ARS), короткое описание, ссылка на товар.
Бейджи — реальные факты из `docs/content-guide.md` (возрастной диапазон,
5 уровней высоты, «línea nueva»), не выдуманные скидки — старый
плейсхолдер `-20%` не был подтверждённым, убран.

Технические решения:
- Если товар с указанным ID вдруг удалят — слайд просто не рендерится
  (`array_filter`), а не фатальная ошибка; если удалят все — весь
  паттерн возвращает `return;` до вывода разметки.
- Функция сборки слайда — **closure в переменной, не именованная
  функция**: файлы паттернов может `require`-ить не один раз за запрос
  (явная регистрация + собственное сканирование редактора блоков),
  именованная `function` дала бы fatal «cannot redeclare» при повторном
  подключении.
- Один настоящий `<h1>` на странице (первый слайд) — у остальных
  слайдов визуально идентичный `<p role="heading" aria-level="1">`,
  чтобы не плодить второй-третий `<h1>` (SEO/доступность), но сохранить
  визуальную идентичность между слайдами.
- `fetchpriority="high"` на фото первого слайда (LCP), `loading="lazy"`
  на остальных.

CSS/JS carousels не трогали — тот же `.js-swiper`/`carousels.js` из
задачи 003, слайды просто стали полнее по содержимому.

## Правки после локального просмотра — раунд 1

Заказчик посмотрел локально, отметил: карусель «кривая косая», фон
слайдов слишком блёклый, на мобильном лишнее фото, стрелки/точки
выглядят «дёшево» — дефолтные Swiper. Заодно всплыла отдельная ошибка
(не про hero): `Undefined array key "queryId"` наверху страницы.

- Высота слайда раньше зависела от длины текста конкретного товара —
  отсюда «кривизна» между слайдами. Зафиксирована:
  `min-h-[420px] md:min-h-[520px]` на каждом слайде.
- Фон слайдов был `from-*/15-25 via-base` — почти белый. Усилен до
  `/30-40` с `via-base-2` (тёплый крем вместо белого).
- Фото товара скрыто на мобильном (`hidden md:flex`) — остаётся только
  офер-блок.
- Свои стрелки на иконках Lucide (`maderamas_icon('chevron-left'/'chevron-right', ...)`)
  вместо дефолтного глифа Swiper, точки крупнее с активной-пилюлей.
- `Undefined array key "queryId"`: у `woocommerce/product-collection`
  в `product-highlights.php` не было атрибута `queryId` (в
  `archive-product.html` — был). Добавлен `queryId:1`.
- Отдельно найден и исправлен **баг в `maderamas_icon()`**
  (`functions.php`, задача 010): файлы `lucide-static` начинаются с
  `<!-- @license ... -->` перед `<svg`, из-за чего якорь `^<svg` в
  `preg_replace()` никогда не матчился — атрибуты `class`/`aria-hidden`
  не подставлялись ни в одну иконку сайта с момента её написания. Это
  первое реальное использование хелпера — раньше не проявлялось.
- 24px зазор между шапкой и hero — `blockGap` WordPress на первом
  потомке `<main>` (`templates/front-page.html`), убран через
  `style.spacing.blockGap:0` на самом `<main>`.

## Правки после локального просмотра — раунд 2

Смещение вправо на десктопе и стрелки на мобильном не исчезли после
раунда 1. Разобрано до конца, обе причины подтверждены структурно (не
на глаз):

1. Блок hero нёс классы `has-global-padding` **и** `alignfull`
   одновременно (следствие `layout:"constrained"`). WordPress
   компенсирует `has-global-padding` отрицательным margin только
   когда `alignfull` — **потомок** `has-global-padding`, не тот же
   узел — так что 24px паддинг слева/справа никуда не девался, и
   карусель не была настоящим edge-to-edge. Подтверждено грепом по
   классам в отданном HTML. Фикс: `layout:"flow"` вместо
   `"constrained"` (центрирование контента и так своё, внутри слайда).
2. `wp_enqueue_style` грузит `maderamas-styles` (наш CSS) раньше
   `maderamas-vendor-styles` (CSS Swiper, приходит через JS-импорт в
   `carousels.js`). Собственный CSS Swiper (`swiper/css/navigation`)
   держит `left`/`right`/`display` на тех же классах
   `.swiper-button-prev`/`-next` — при равной специфичности выигрывает
   **позже подключённый** файл, то есть Swiper, а не наши правила.
   Подтверждено прямой проверкой порядка `<link>` в HTML и содержимого
   `build/index.css`. Фикс: все правила `.maderamas-hero-nav*`
   заскоуплены через родителя `.maderamas-hero` (выше специфичность
   независимо от порядка файлов) + `!important` на позиционировании и
   мобильном `display:none` — там, где нужна 100% гарантия, а не
   просто более высокая специфичность.

Заодно — по просьбе «крупнее, но менее активно»: стрелки `2.75rem` →
`3.5rem`, сплошной фон → полупрозрачный через `color-mix()` (не новый
хардкод-цвет, смешение уже существующего токена `surface` с
прозрачностью), убран агрессивный hover (была заливка `primary` +
`scale`, стал только рост непрозрачности фона).
