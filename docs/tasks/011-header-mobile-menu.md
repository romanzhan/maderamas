# 011 — Шапка: мобильное меню

**Статус:** готово, 2026-08-18.

## Зачем

Прямая правка от заказчика по ходу задачи 010: «шапку мобильной версии
проработай нормально, сделай обычный но понятный и красивый бургер, с
выезжающим меню, потому что то меню что сейчас ужасно целиком».

## Что было

`core/navigation` с `overlayMenu:"mobile"` — встроенная модалка блока
(WordPress сам решает, когда показывать хамбургер/оверлей, стилизуется
плохо и не даёт контроля над анимацией/фокусом). При этом сам `<nav>`
уже был помечен `hidden lg:flex` (наше собственное переопределение под
десктопный вариант) — то есть блок и его точка входа фактически не
были согласованы друг с другом.

## Что сделано

- `wp:navigation` переключён на `overlayMenu:"never"` — блок больше не
  рендерит свою кнопку/модалку вообще (проверено: 0 вхождений
  `wp-block-navigation__responsive-container-open` в отданном HTML).
  Остаётся только как источник плоского списка ссылок для десктопа
  (`hidden lg:flex`, без изменений).
- Полностью своя мобильная панель в `parts/header.html`: кнопка-бургер
  (`.icon-btn`, 44×44px, иконка `menu` из Lucide инлайном — `parts/*.html`
  не выполняет PHP, поэтому `maderamas_icon()` тут недоступен;
  SVG скопирован из `assets/icons/menu.svg` дословно) + панель, выезжающая
  слева (backdrop с затемнением + сама панель с логотипом, крестиком
  закрытия, списком ссылок и кнопкой `.btn-primary` «Ver catálogo» внизу).
- `src/mobile-menu.js` — открытие/закрытие, фокус-ловушка (Tab/Shift+Tab
  не выходит за панель), закрытие по Esc/клику на backdrop/клику по
  ссылке, блокировка скролла страницы (`overflow-hidden` на `body`),
  `inert` на закрытой панели (не в таб-порядке и недоступна скринридеру),
  возврат фокуса на кнопку-бургер при закрытии. Подключено в `src/index.js`
  рядом с уже существующей инициализацией каруселей.
- CSS: закрытое состояние задано прямо в разметке через утилиты Tailwind
  (`hidden`, `opacity-0`, `-translate-x-full`) — так меню корректно
  выглядит, даже если скрипт ещё не догрузился; классы `is-open`/
  `is-visible` (добавляет только JS) описаны отдельно в `src/style.css`,
  не через `@layer components` (там, что и в 010 — фильтрация Tailwind
  по content-скану). Для `lg+` панель принудительно скрыта через
  `lg:!hidden`, отдельно от JS-состояния — подстраховка, чтобы её нельзя
  было увидеть на десктопе ни при каких условиях.
- Заодно проработаны иконки-кнопки мини-корзины и входа в аккаунт
  (`woocommerce/mini-cart` и авто-вставляемый Woo `customer-account`) —
  их разметку рендерит сам блок, поэтому стилизованы напрямую по
  реальным классам (`wc-block-mini-cart__button` и т.п., BEM с `__`,
  `stylelint-disable selector-class-pattern` на этот блок — имена чужие,
  переименовать нельзя) с теми же токенами (`var(--wp--preset--color--*)`),
  44×44px, hover/active/focus-visible.

## Проверено (без браузера)

- `npm run build`/`lint:js`/`lint:css` — чисто.
- `curl` на `/`, `/shop/`, товар, `/cart/` — везде 200.
- В отданном HTML: разметка мобильного меню присутствует,
  `wp-block-navigation__responsive-container-open` — 0 вхождений
  (блок больше не рендерит свой хамбургер).
  В собранном CSS: `.icon-btn`/`.btn-primary` теперь реально
  компилируются (используются в `header.html`), `.lg\:\!hidden`
  корректно генерит `display:none !important` от 1024px.
  В собранном JS: строки-селекторы `data-mobile-menu`/`is-visible`
  присутствуют в бандле.
- `wp-content/debug.log` — новых PHP-ошибок/предупреждений от этой
  правки нет (есть старые, не связанные, от WooCommerce
  `ProductCollection\Renderer` — существовали и до этой задачи).
