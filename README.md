# maderamas.com.ar

Интернет-магазин детской мебели. WordPress + WooCommerce, собственная блочная тема,
собственный слой перевода.

## Что лежит в этом репозитории

Только наш код. Ядро WordPress, сторонние плагины, загруженные файлы и база данных
сюда не попадают — см. `.gitignore` и `docs/plugins.md`.

```
.wp-env.json                       описание локальной среды (версии WP, PHP, плагинов)
bin/setup-env.mjs                  первичная настройка свежей локальной установки
wp-content/themes/maderamas/       блочная (FSE) тема — весь дизайн
wp-content/mu-plugins/             бизнес-логика магазина
  maderamas-loader.php               загрузчик модулей
  maderamas-core/                    общие настройки и безопасность
  maderamas-i18n/                    слой перевода
  maderamas-woo/                     настройки WooCommerce
docs/                              документация и архитектурные решения
```

Бизнес-логика намеренно живёт в `mu-plugins`, а не в теме: замена или правка темы
не должна ломать магазин.

## Быстрый старт

Нужны: [Docker Desktop](https://www.docker.com/products/docker-desktop/) и Node.js 22+.
PHP, Composer и WP-CLI локально ставить не надо — они работают внутри контейнера.

```bash
# 1. Запустить Docker Desktop и убедиться, что демон отвечает
docker version

# 2. Зависимости
npm install

# 3. Поднять WordPress
npm run env:start

# 4. Настроить свежую установку (локаль, тема, WooCommerce, ссылки)
npm run env:setup

# 5. Собрать ассеты темы
npm run build
```

Сайт: <http://localhost:8888> · Админка: <http://localhost:8888/wp-admin> (`admin` / `password`)

Во время работы над стилями держите запущенным `npm run start` — пересборка на лету.

### Скорость локального сайта

Страница открывается за 8–11 секунд, и это ожидаемо. Причина не в коде: `wp-env`
монтирует ядро WordPress и все плагины с диска Windows внутрь Linux-контейнера,
а на запрос читается около 1500 PHP-файлов, каждый — через границу файловых систем.
Замеры на этом проекте:

| Что | Время |
| --- | --- |
| Отдача статики | 0,1–0,7 с |
| Главная без WooCommerce | ~3 с |
| Главная с WooCommerce | 8–11 с |
| Первый запрос после перезапуска (прогрев OPcache) | до 50 с |

OPcache включён и работает штатно — он тут не виноват, кэш не переполняется.
Если скорость начнёт мешать работе, радикальное решение — перенести проект
в файловую систему WSL2 и запускать `npm` оттуда; тогда файлы окажутся на стороне
Linux и граница исчезнет. Более дешёвый вариант на время чисто дизайнерских задач —
временно отключить WooCommerce: `npm run wp -- plugin deactivate woocommerce`.

На проде этой проблемы нет — там обычная файловая система Linux.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run env:start` / `env:stop` | поднять / остановить локальный WordPress |
| `npm run env:destroy` | снести среду вместе с базой (данные не восстановить) |
| `npm run env:setup` | привести свежую установку в рабочий вид |
| `npm run start` | сборка ассетов в режиме наблюдения |
| `npm run build` | продакшн-сборка ассетов |
| `npm run lint` | все линтеры: JS, SCSS, PHP |
| `npm run makepot` | пересобрать `.pot` со строками темы |
| `npm run wp -- <команда>` | выполнить WP-CLI внутри контейнера |

Пример: `npm run wp -- plugin list`

## Процесс работы

- Ветка `main` защищена, прямых пушей нет.
- Работа идёт в коротких ветках `feat/*`, `fix/*`, `docs/*` → Pull Request → squash-merge.
- Сообщения коммитов — [Conventional Commits](https://www.conventionalcommits.org/):
  `feat: agregar filtro por color`, `fix: corregir precio en variaciones`.
- CI на каждый PR прогоняет линтеры и сборку. Красный CI не мержим.

## Правила, которые легко нарушить по невнимательности

1. **Цвета, размеры и отступы — только через `theme.json`.** В SCSS используем
   переменные `var(--wp--preset--…)`. Хардкод-значения ломают дизайн-систему.
2. **Все строки в PHP — через `__()` / `esc_html__()`** с текстовым доменом `maderamas`.
   Это фундамент слоя перевода: строка без обёртки не переведётся никогда.
3. **Никаких секретов в git.** Ключи Mercado Pago, SSH-ключи, пароли — только
   в переменных окружения на проде и в GitHub Secrets.
4. **Правка файлов через админку запрещена** (`DISALLOW_FILE_EDIT`). Всё изменяется
   через git, иначе следующий деплой молча затрёт правки.
5. **Контент едет только с прода на локалку, код — только с локалки на прод.**
   См. `docs/deploy.md`.
