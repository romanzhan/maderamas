# Инструкции для Claude Code

Проект: `maderamas.com.ar` — интернет-магазин детской мебели.
WordPress 7.0 + WooCommerce, PHP 8.3, рынок Аргентины, основной язык es-AR.

**Перед началом работы прочитайте `CONTEXT.md`** — там текущее состояние
серверов, история решений по хостингу и открытые задачи. Этот файл здесь —
про стандарты кода, `CONTEXT.md` — про то, что сейчас происходит с проектом.

## Архитектура в двух абзацах

В git живёт только наш код: блочная тема `wp-content/themes/maderamas` и модули
в `wp-content/mu-plugins`. Ядро WordPress, сторонние плагины, `uploads` и база
данных не версионируются. Локальная среда — `@wordpress/env` (Docker), описана
в `.wp-env.json`.

Бизнес-логика лежит в `mu-plugins`, а не в теме. Тема отвечает только за оформление.
WordPress загружает из `mu-plugins` только файлы в корне каталога, поэтому модули
из подпапок подключает `maderamas-loader.php` — новый модуль надо добавить в его список.

## Обязательные правила

- **Стандарты кода** — WordPress Coding Standards, конфиг в `phpcs.xml.dist`.
  Отступы табами, Yoda-условия, докблоки. Проверка: `npm run lint`.
- **Префиксы.** Все глобальные функции, классы и константы начинаются с `maderamas_`
  (классы — `Maderamas_`). Стандарт отклоняет префиксы короче четырёх символов,
  поэтому сокращения вроде `mdr_` не подходят. Файл с классом называется
  `class-maderamas-<имя>.php`.
- **Интернационализация.** Любая строка, видимая пользователю, оборачивается
  в `__()` / `esc_html__()` / `esc_attr__()` с доменом `maderamas`.
  Строка без обёртки не переведётся — это не стилистика, а поломка функциональности.
- **Экранирование.** Вывод — через `esc_html()`, `esc_attr()`, `esc_url()`, `wp_kses_post()`.
  Ввод — через `sanitize_*()`. Все формы и AJAX — с проверкой nonce и прав.
- **Дизайн-токены.** Цвета, шрифты, отступы задаются в `theme.json`. В SCSS
  берём их как `var(--wp--preset--color--primary)` и подобные. Хардкод запрещён.
- **Секреты.** Ключи API, пароли, SSH-ключи в репозиторий не коммитим никогда.
- **WooCommerce.** Перед регистрацией хуков Woo проверяем `class_exists( 'WooCommerce' )` —
  иначе отключение плагина уронит сайт.

## Слой перевода

Своя реализация вместо WPML/Polylang. Модель: **один пост на все языки**,
переводы в `post_meta` через `Maderamas_Lang::meta_key()`. Посты по языкам
не дублируем — у товара должны оставаться единые цена и остаток на складе.

Язык по умолчанию `es` идёт без префикса в URL, остальные — с префиксом (`/en/…`).
Реестр языков — константа `Maderamas_Lang::LANGUAGES`.

## Известная особенность зависимостей

В `package.json` есть `overrides: { "typescript": "^5.3.3" }`. Он нужен, потому что
`@wordpress/scripts` тянет `@typescript-eslint` 6.x, который читает внутренние API
TypeScript и ломается на TypeScript 7 с ошибкой `Cannot read properties of undefined
(reading 'Intrinsic')`. Сам TypeScript в проекте не используется. Убирать этот
override можно только после того, как `@wordpress/scripts` перейдёт
на `@typescript-eslint` 8.x.

## Чего делать не надо

- Не добавлять page builder'ы (Elementor и подобные) — вёрстка должна оставаться в git.
- Не ставить платные плагины с подпиской: заказчик от них уходит осознанно.
- Не дублировать посты для перевода.
- Не писать стили в `style.css` темы — он нужен только ради заголовка темы.
- Не деплоить базу данных и `uploads` — контент живёт на проде.

## Проверка работы

```bash
npm run lint          # линтеры JS, SCSS, PHP
npm run build         # сборка ассетов
npm run env:start     # локальный WordPress на localhost:8888
```

Перед тем как объявить задачу выполненной, прогоните линтеры и убедитесь,
что страница реально открывается в браузере.
